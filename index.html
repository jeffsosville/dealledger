How It Works

01 — OBSERVE

Scrape marketplaces + brokers

Daily scrapes from BizBuySell (40,000+ marketplace listings) and 1,700+ individual broker websites. Two sources, one ledger.

02 — TIMESTAMP

Recover listing dates

Marketplaces hide listing dates. We reverse-engineer them from sequential listing IDs calibrated against known anchors. Mean error: ±12 days.

03 — PUBLISH

Open API + GitHub

Marketplace data in a public Supabase database — queryable by anyone. Broker-direct data committed to GitHub daily. All CC0.

04 — MEASURE

Liquidity intelligence

Days on market, zombie rate, disappearance detection, state-level liquidity index. Published monthly in the SMB Liquidity Report.

Principles

→ Source-linked. Every record traces back to its original broker page.

About DealLedger

The problem: There is no public registry for small business transactions. The same listing appears across multiple sites, listing dates are hidden, and inventory numbers are inflated by stale and zombie listings. The market is opaque by design.

What this is: DealLedger is an open public ledger for businesses for sale. We collect listings from marketplaces and broker websites, recover listing dates through our sequential ID methodology, and publish everything as open data.

What this isn't: We don't rank listings. We don't recommend brokers. We don't capture leads. We don't broker deals. This is a record, not a marketplace.

How it works: Two data layers — marketplace listings (BizBuySell, 40k+ records, daily updates via Supabase API) and broker-direct listings (1,700+ broker sites, 9,600+ records, committed to GitHub daily). The methodology is documented. The code is open. Anyone can verify and build on it.
